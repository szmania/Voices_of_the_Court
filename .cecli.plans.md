# VOTC-151: Agentic Memory Compaction System

## 1. Project Overview
- **Filled out by**: project_manager
- **Problem Statement**: Long Crusader Kings III campaigns with VOTC-CE (with active LLM integration enabled) accumulate substantial event/memory data in the agent's internal state. Users report performance degradation and memory bloat in extended sessions (multi-year campaigns with lively families/empires). Current architecture stores memories in full-uncompressed text format using `js-tiktoken` for tokenization, which doesn't optimize for reusable context patterns across years and lineages.
- **Project Objectives**: Implement a two-phase memory compaction system with intelligent context preservation:
  - **Phase 1: Context-Aware Token Reduction** — Semantic similarity clustering, sentiment aggregation, period-based summarization, family tree optimization
  - **Phase 2: Hierarchical Memory Indexing** — Inverted indexes, causal chain preservation, rolling uncompressed window
- **Scope**: 
  - In-scope: Memory compaction engine, SQLite-backed index schema, IPC protocol for compaction, settings panel integration, validation suite
  - Out-of-scope: External ML model training, GPU-accelerated processing, real-time compaction during gameplay
- **Success Criteria**: 70% memory reduction for 10-year campaigns, >95% context accuracy, <200ms compaction time, cross-language equivalence (EN, ZH, RU, FR, ES)

## 4. Problem Analysis and Goals
- **Filled out by**: project_manager
- **Problems**:
  1. Memory bloat in extended CK3 campaigns with VOTC-CE
  2. Performance degradation over multi-year gameplay sessions
  3. Redundant storage of identical/similar memories (e.g., 50 copies of identical compliments)
  4. Linear event logs for family relationships instead of optimized maps
  5. No mechanism to distinguish critical events from routine ones
- **Goals**:
  1. Reduce memory footprint by 70% for 10-year campaigns
  2. Maintain >95% context accuracy after compaction
  3. Preserve causal chains and critical narrative events
  4. Support all 5 supported languages (EN, ZH, RU, FR, ES)
  5. Provide user-configurable compaction settings
- **Why Needed**: To enable extended gameplay sessions without technical degradation, improving user experience for long-running campaigns
- **Bottlenecks**:
  1. Tokenization overhead with `js-tiktoken`
  2. Semantic similarity computation complexity
  3. Cross-language embedding consistency
  4. IPC communication overhead between renderer and main process

# Research: Missing `VOTC:IN/;/init` Marker During Letter Delivery

**Date**: 2026-06-07 | **Status**: Complete

---

## Executive Summary

The `VOTC:IN/;/init` marker is missing from the CK3 `debug.log` during letter delivery because it is **only written when the player initiates a new conversation with an NPC**. During normal gameplay, no conversation initialization occurs, so `parseLog()` returns `undefined` and letter delivery silently fails.

---

## 1. How `VOTC:IN/;/init` Is Generated (CK3 Mod)

The marker is generated by the **CK3 companion mod** (`debug_log` commands in .txt scripts), NOT by the Electron app.

### Generation Workflow:
1. Player clicks "Talk to [NPC]" in CK3
2. Mod writes `VOTC:IN/;/init` + all character data to debug.log
3. Mod copies `VOTC:IN` to clipboard
4. Desktop app `ClipboardListener` polls clipboard every 100ms, detects it
5. `ClipboardListener` emits `'VOTC:IN'` event, handler calls `parseLog()`

### Supported Commands (ClipboardListener.ts lines 49-71):
`IN`, `EFFECT_ACCEPTED`, `BOOKMARK`, `SUMMARY_MANAGER`, `CONVERSATION_HISTORY`, `LETTER`, `LETTER_ACCEPTED`

### When It IS Written: ONLY during conversation initialization.
### When It Is NOT Written: Normal gameplay, date advancing, letter generation/receipt.

---

## 2. How parseLog() Consumes the Marker

From `src/shared/gameData/parseLog.ts`:
- Reads debug.log from end backward in **256KB chunks**
- Searches for last occurrence of `VOTC:IN/;/init`
- If found: extracts everything from there to end-of-file and parses it
- If NOT found: returns **undefined**

---

## 3. The Letter Delivery Code Path (THE BUG)

In `src/main/main.ts`, `checkAndDeliverLetters()` at line ~325:
```typescript
const gameData = await parseLog(path.join(config.userFolderPath, 'logs', 'debug.log'));
if (!gameData) {
    console.error('Could not parse game data during letter delivery...');
    continue;  // <--- LETTER DELIVERY SILENTLY SKIPPED
}
const currentDateString = gameData.date;
letterManager.deliverLetter(storedLetter, config, currentDateString);
```

What gameData is actually used for: **only `gameData.date`** for the delivery timestamp.

---

## 4. All parseLog() Call Sites in main.ts

| Line | Context | Fails without VOTC:IN? |
|------|---------|------------------------|
| ~325 | `checkAndDeliverLetters()` | **YES** -- silently skips |
| ~945 | `clipboardListener.on('VOTC:IN')` handler | N/A -- this IS where VOTC:IN should exist |
| ~1127 | `clipboardListener.on('VOTC:LETTER')` handler | **YES** -- same vulnerability |
| ~1406 | Date retrieval helper | May fail, has fallback |

---

## 5. Root Cause Analysis

`parseLog()` was designed for conversation initialization only. It was reused in letter delivery without considering that:
- No conversation needs to be happening when letters are due
- The last conversation init block may be far back in the log (beyond 256KB chunk)
- CK3 may rotate/truncate debug.log, removing old markers entirely

### Three Failure Scenarios:
1. **Normal gameplay** (MOST COMMON): Letters due while player is unpaused, no recent conversation init.
2. **Large log file**: Conversation was started too long ago to be within 256KB of file end.
3. **Log rotation**: CK3 truncated old debug.log, removing all VOTC:IN markers.

---

## 6. The Better Pattern Already Exists: LETTER_ACCEPTED Handler

The `VOTC:LETTER_ACCEPTED` handler at line ~1043 does NOT call parseLog(). Instead:
```typescript
const deliveryDateString = totalDaysToDateString(currentTotalDays);
```
`currentTotalDays` is continuously tracked via:
1. `initCurrentDateFromLog()` -- scans log for VOTC:DATE on startup
2. `startLogTailing()` -- watches debug.log for new VOTC:DATE lines
3. `processLogLine()` -> `updateCurrentDate()` -- sets currentTotalDays

---

## 7. Recommended Fix (Simplest)

In `checkAndDeliverLetters()`, replace the parseLog() call with:
```typescript
const currentDateString = totalDaysToDateString(currentTotalDays);
```

And remove the conditional check on gameData being undefined for line ~325.

The same pattern should be applied at line ~1127 (`VOTC:LETTER` handler).

### Why This Works:
- `currentTotalDays` is already being tracked reliably via log tailing
- The LETTER_ACCEPTED handler already uses this exact pattern successfully
- Single-line change, minimal risk, eliminates the dependency on parseLog() entirely for letter delivery
- Consistent with how the rest of the letter system handles dates

---

## 8. Files Requiring Changes (Fix A)
1. **`src/main/main.ts`** -- `checkAndDeliverLetters()` (~line 325): Remove parseLog() call, use `totalDaysToDateString(currentTotalDays)` instead.
2. **`src/main/main.ts`** -- `VOTC:LETTER` handler (~line 1127): Same fix for incoming letter processing.

---

## 9. Additional Observations
- The error message "Could not parse game data during letter delivery" is misleading -- it suggests mod conflict when the real issue is a design mismatch between parseLog()'s assumptions and letter delivery's context.
- The original error from conversation init says "This is most likely a mod conflict" but for letter delivery this is expected behavior.
- No actual mod conflict is needed to trigger this bug.
